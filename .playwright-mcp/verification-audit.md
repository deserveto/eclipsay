## High priority findings

1. **Guest migration RPC is callable as a public SECURITY DEFINER function.** `supabase/migrations/0002_migrate_guest.sql:6-16` creates `public.migrate_guest_data` with `security definer`, accepts caller-controlled `p_user_id`, and never checks `auth.uid()`. There is no `REVOKE EXECUTE`/restricted `GRANT` in the migrations. PostgreSQL functions default to EXECUTE for PUBLIC, so the PostgREST RPC surface can bypass the route's auth check and write through all owner tables. The route's check is only `src/app/api/migrate/guest/route.ts:17-24`; it cannot protect direct RPC calls. Revoke EXECUTE from PUBLIC/anon/authenticated and expose it only to the intended server role, or move it to a private schema and enforce ownership inside the function.

2. **Chat request validation is effectively untyped and unbounded.** `src/app/api/chat/route.ts:25-35` uses `z.custom<UIMessage>()` with no runtime predicate, and has no maximum message count, parts count, or text/metadata size. `joinText` immediately dereferences `message.parts` at `:38-43`, so malformed JSON can produce an uncaught 500; oversized valid-looking payloads can force expensive model conversion/prompt work. The endpoint is guest-accessible (`:59-62`) and calls the model at `:211-233`. Add structural validation and hard request/token limits.

3. **No application rate limiting or quota exists for anonymous AI spend.** There is no rate-limit implementation or provider such as Upstash in the repository. Guest or unauthenticated callers can repeatedly invoke `/api/chat` (`:59-62`, model call `:211-233`), `/api/journal-assist` (`:23-25`, `:43-56`), and guest title generation (`src/app/api/sessions/[sessionId]/title/route.ts:26-29`, `:65-82`). Draw/clarify and anonymous analytics endpoints are also unthrottled. This permits cost exhaustion and resource abuse before production launch.

## Other concrete issues

- **Missing security headers.** `next.config.ts:3-5` is empty; a production `HEAD /` check returned `X-Powered-By: Next.js` and no CSP, HSTS, frame, nosniff, referrer, or permissions headers. Configure headers and disable the powered-by header at the deployment boundary.
- **Cross-user foreign-key integrity is not enforced.** `src/app/api/followups/route.ts:6-10,33-45` accepts arbitrary session/journal UUIDs and inserts them with the current user's `user_id`; `0001_init.sql:65-70` has independent FKs and `:116-117` only scopes follow-ups by their own user. Tarot draws have the same independent `session_id`/`user_id` shape (`src/lib/tarot/draw-service.ts:40-49`, `0001_init.sql:31-38`). Add ownership checks or composite owner FKs to prevent cross-tenant references and cascade surprises.
- **Signup enumerates registered emails.** Despite the non-enumeration comment in `src/components/auth/login-form.tsx:19-21`, the server maps duplicate Supabase errors to `email_taken` and returns it at `src/app/api/auth/signup/route.ts:41-50`. An unauthenticated caller can probe account existence. Use generic signup errors and keep recovery copy client-side only when appropriate.
- **Migration count is wrong.** `supabase/migrations/0002_migrate_guest.sql:18-37` assigns `imported` from the sessions insert and never increments it for readings, messages, journal entries, or memories; the route returns that misleading count at `src/app/api/migrate/guest/route.ts:47-51`.
- **Analytics contract is not enforced.** `src/app/api/events/route.ts:14-29` accepts any event name up to 64 characters (rather than the `AnalyticsEvent` union) and an arbitrary-depth/unbounded metadata object, while allowing anonymous writes. Add an allowlist, metadata bounds, and throttling/retention.
- **Operational controls are absent.** There is no CI workflow, deployment manifest, health/readiness endpoint, instrumentation/Sentry config, or app-level `error.tsx`/`global-error.tsx`/`not-found.tsx`/`loading.tsx`. The only server logging is unstructured `console.error` in route handlers, including provider/Supabase error objects; redact and centralize logs before handling private reflection data in production.
- **Lint signal is noisy.** `eslint.config.mjs:15-21` ignores standard build folders but not the repository's local `.agent`, `.agents`, `.codex`, `.impeccable`, `.opencode`, and `.playwright-mcp` trees, producing 584 warnings with a green exit. Ignore tooling folders or lint only product paths in CI.
